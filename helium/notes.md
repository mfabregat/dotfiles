# Helium theme — gruvbox #282828

> Colors come from the repo-wide source of truth: `palette/palette.json`
> (see `palette/README.md`). The manifest is regenerated with
> `python3 palette/generate.py` — do not edit the colors here by hand.

## Setup (current, working)

A minimal **color-only theme extension** (no images, no JS) lives in this repo at
`.config/net.imput.helium/themes/gruvbox-282828/manifest.json` and is stowed to
`~/.config/net.imput.helium/themes/gruvbox-282828/`.

It is auto-loaded on every launch via the wrapper flags file
`.config/helium-browser-flags.conf` (stowed to `~/.config/helium-browser-flags.conf`):

```
--load-extension=/home/marc/.config/net.imput.helium/themes/gruvbox-282828
```

Re-apply after changing the manifest: `cd ~/dotfiles && stow -R helium`.
(The wrapper escapes `$`/`~`, so the path must be absolute.)

### Why a theme extension instead of the native `autogenerated.theme.color`

The native Preferences value can only make the **frame** exactly `#282828`; it
forcibly *lightens* the toolbar/tab strip (minimum ≈ `#353535`) and derives the
omnibox pill, so the prominent top bar can never be `#282828`. A color-only theme
extension sets `frame`/`toolbar`/`tab_text`/… directly — everything becomes
exactly `#282828` (with gruvbox `#EBDBB2` text). Verified empirically on Helium
151.

### Caveats (derived colors the theme cannot control)

- **Omnibox pill**: derived as `BlendForMinContrast(toolbar, toolbar, …, 1.3)`
  → `#3B3B3B` (forced 1.3:1 contrast against the toolbar; with `#282828` the
  dark endpoint can't reach it, so it lightens).
- **Focused omnibox** shows a thin system-accent focus ring (`#BAC3FF`).
- **Toolbar top separator** ≈ `#3E3E3E`; toolbar *icons* use default greys.
- sway's window border is **not** the browser: `client.focused #665c54` /
  `client.unfocused #282828` (`~/.config/sway/config.d/looks`).

## Old approach (native autogenerated theme) — reference only

Sources: brave-browser issues #42358, #39629, matthieudesprez/brave-profile-manager.

**NOTE: the two numbers below are WRONG (RGB without alpha):**
`2631720` = `0x00282828`, `3289650` = `0x00323232`. Both make Chromium composite
a transparent color over white, yielding a muddy `#58585A` toolbar / `#39393B`
frame.

The Preferences value must be the **signed 32-bit ARGB** of the color:
`0xFFRRGGBB` re-read as int32. For `#282828` → `0xFF282828` → **`-14145496`**.

1. Close Helium completely.
2. Edit `~/.config/net.imput.helium/Default/Preferences`:
   - set `"extensions": { "theme": { "id": "autogenerated_theme_id" } }`
   - add `"autogenerated": { "theme": { "color": -14145496 } }`
3. Relaunch. (`user_color2`/`color_variant2` keys are Brave-only, not Helium.)

### What the native pipeline produces from the value

`GetAutogeneratedThemeColors()` (chrome/common/themes/autogenerated_theme_util.cc)
derives everything from the single input color:

| surface | rule | with `-14145496` |
|---|---|---|
| frame / tab-strip bg | kept as input (≥7:1 contrast vs derived text) | `#282828` exact |
| toolbar / tab strip | always lightened (`LightenUntilContrast` 1.3–1.7:1) | `#484848` |
| omnibox pill | `BlendForMinContrast(toolbar, …, 1.3)` | `#373738` |
| NTP bg | = toolbar color | `#484848` |
